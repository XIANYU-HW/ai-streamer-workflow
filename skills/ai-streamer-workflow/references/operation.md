# 运行与故障处理

仓库 runtime 是可注入适配器的调度核心，默认没有真实游戏/模型/推流驱动。读 `packages/runtime/INTEGRATION.md` 按现有 API 接入；不要杜撰客户端接口或假装全部平台可用。

- 本地程序处理高频观测、控制、停止；AI 批量提出有界策略，异步更新。思考时可以继续已验证且适合当前状态的操作，不能盲目重放危险输入。记录策略来源与实际效果。
- 只有一个租约文件/状态源决定控制权。取得新租约不代表游戏真的获得焦点，必须用适配器观测核对。租约过期/停止应释放输入，失败保留首因并升级。
- 只有一个语音队列执行播放，互动和搭档对话都排入该队列。礼物需要可信真实事件 ID；模拟礼物有 simulated 标识。按事件 ID 去重，播放结果未知时查回执，不盲目重播。
- 记录 receivedAt、replyReadyAt、speechStartedAt；观众体验看 `speechStartedAt - receivedAt`。给出真实样本、P50/P95与最大延迟，未知时间不填零。队列拥堵时合并普通弹幕/闲聊，不丢真实礼物账目。
- 正式玩家默认每 900 秒轮换。时钟在实际节目开始条件满足时起算；局部故障、换 Agent 或换适配器不能重置。画面显示两主播名称、当前玩家、剩余时间，只按实际控制权更新。
- 局部游戏/语音/互动/录制故障分别恢复。严重故障时导播放“遇到了些问题，请稍等”待机图；保持安全输出，保留原节目时钟。用户停止优先于任何“保持直播”策略。
- 游戏辅助默认由玩家请求、逐步增强，相邻生效修改间隔可配置（模板 30 分钟），重启不清零；新用户可以明确调整该策略。适配首次实现和正式游玩中改变挑战强度应分别记录。

用户设置的直播软件优先，核心不强制 OBS 或特定平台。导播必须独立验证平台可接受的画面和两条声线；有播放器成功、桌面声音或本地预览不等于观众已能听见。等待图、滚动弹幕、音乐可以按用户需求配置；音乐/人物资源须由使用者提供可用权利。

本包中的模拟仅用于工程验证，不能直接宣布正式开播已就绪。公开直播、录制及付费调用按用户当次授权执行，配置不新增授权。系统安全验证由用户在设备上完成，不能绕过。

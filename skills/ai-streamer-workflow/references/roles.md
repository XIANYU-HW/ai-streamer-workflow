# 岗位与能力契约

所有岗位均由使用者选择 AI、模型和档位。下面规定产物与责任，不指定供应商。岗位可以对应项目对话或支持隔离职责的代理；高频动作应由本地适配程序执行，不能依靠每步跨会话传话。

| ID / 岗位 | 职责与产物 | 需要的能力 | 触发与边界 |
|---|---|---|---|
| coordinator / 项目统筹 | 当前任务、依赖、唯一文件归属、配置状态、可执行交接 | 需求拆解、工具发现、结果核验 | 按需调度；不代替玩家持续操作 |
| broadcast-director / 直播导播 | 场景、字幕/轮换倒计时、待机画面、音画监看、录制/输出证据 | 直播软件控制、画面/音频观测 | 节目期间工作；抢前台前先取得租约；不能将单声道有电平当双声线验收 |
| gameplay-performer / 游戏实况执行 | 自主游玩、可验证画面变化、两主播游戏实况、唯一发声队列 | 游戏状态观测、决策、低延迟适配器控制 | 持唯一游戏控制权；决策与控制并行；不等待无关部件修复；不把固定脚本冒充不同模型决策 |
| audience-manager / 观众互动管理 | 标准化弹幕/礼物、优先级、去重、拟人化回应候选、端到端延迟 | 实时事件读取、角色一致的对话和内容处理 | 只交候选给唯一发声消费者；不自行同时播放声音，不控制游戏 |
| game-adaptation-engineer / 游戏适配工程师 | 游戏可观测/可控协议、低延迟执行器、停止与释放验证、适配说明 | 操作系统与游戏输入工程、状态提取、诊断 | 初次适配或玩家明确请求时介入，交付后待命；正式玩家策略归玩家，不能常驻改游戏或抢输入 |
| studio-engineer / 舞台与声音工程师 | 空白角色编辑、动态角色/场景、声线配置、播放链路修复 | 应用开发、音频、动画和安全本地存储 | 构建/缺陷时工作；不与执行角色争用输出队列或控制游戏 |
| reviewer / 独立验收 | 针对候选和明确缺陷的独立证据与结论 | 测试设计、媒体检查、证据边界 | 候选齐备或被请求才启动；完成或缺材料就结束，不常驻轮询 |

文件修改由模块唯一作者负责，跨模块需要先直接约定归属。消息只送统筹或实际消费者；不要群发每条日志。交接包含当前版本、状态、首个故障、已验收/未验收、入口及下一步即可。

游戏适配交付最少包含：观测结构、允许动作、输入释放、租约过期处理、实际动作效果证据、平台/游戏版本范围、已知限制、卸载恢复方法。未配置适配器须明确 unavailable。是否修改游戏程序由使用者授权与游戏条件决定；不附游戏副本或别人的存档，不用“通用适配”声称支持未测试的游戏。

主播角色由使用者创建，模型身份与角色名字分开。闲聊应基于当前可观察事实，允许停顿、回应搭档和轻微打趣；建议总计每分钟 3–5 句可调，礼物/关键游戏事件优先，不为凑数量无休止说话。人设规则、声线特征和例句写进用户本地角色资料，仓库不预装作者的人物。

# 安装与配置

1. 源码根目录运行 `npm run setup`。需要 Node.js 22.12+ 和 npm；Windows 可双击 `Setup-Windows.cmd`，macOS/Linux 可运行 `sh setup.sh`。安装依赖会访问软件源；没有调用模型、TTS、游戏或直播平台。
2. Setup 生成 `.local/workflow.json`、`.local/agent-plan/` 和项目内 `.agents/skills/ai-streamer-workflow`。重跑保留已有配置、会话记录和已修改的 Skill。宿主不识别该 Skill 目录时，使用其正规的安装方式，或直接读源码中的 SKILL.md。
3. `npm run doctor` 报依赖和配置状态。`npm run studio` 打开独立的空白舞台软件；这一步由需要使用舞台时执行，setup 不抢占屏幕。
4. 与使用者确认/读取已有选择：操作系统、游戏、直播平台及软件、所用 AI 接口或客户端、角色设定和声线、是否允许付费及额度。已明确的信息不重复询问。模型没有统一推荐档位，按是否支持所需能力判断：视觉或结构化状态读取、工具执行、低延迟文本、上下文预算等。
5. 用 `npm run demo` 验证有限离线模拟。接实际设备时从一个游戏适配器、一条声音和一个本地录制输出开始。后续只验证新增/受影响的部件。

若需要把配置放在另一个项目目录，可用 `npm run setup -- --directory 目标目录`；软件仍从源码仓库启动，配置和岗位提示词存入目标目录，检查时用 `npm run doctor -- --directory 目标目录`。不要移动正在使用的源码仓库而不更新本地岗位入口。

模型能力清单应记录：客户端或 API、模型由谁选择、视觉输入支持、工具/API 能力、输出格式、观测延迟、实测状态。留空不等于宿主会自动提供所有能力。API 密钥只在用户本机供应商设置中输入；不要要求粘贴到聊天或发布文件。

角色会话创建不是 npm 的功能。宿主支持项目对话工具且用户要求创建对话时，为七个岗位分别提交 `.local/agent-plan/<role>.md`，省略用户未指定的模型字段；成功后记录真实会话 ID。保留已有会话，避免重复创建。若工具不支持，则交付角色包和待创建清单。

默认成本关闭；使用者自行选择启用与上限。声线供应商、舞台与 runtime 可能各有成本控制，接入者须保持一致。不能因为其中一个已允许而跳过另一个，也不要继承示例作者的无限授权。
